# 08 · 主持人与创作者生态

> 状态：草案 v0.2 | 关联：[03 密令系统](03-mandate.md)、[04 回响系统](04-echo.md)、[05 无阵营与主持人](05-authority-and-ascension.md)、[07 关卡设计系统](07-level-design.md)

---

## 0. 本文档的地位

《终焉之地》有两个内容供给源：官方设计的基础玩法模板，以及**编号自己创造的关卡**。前者是地板，后者是天花板。

同时，本作有一个绕不开的硬性门槛：**开局人数由关卡作者设定，多数有张力的关卡要 8 人以上才凑得起来**。在冷启动阶段，这个门槛足以杀死整个产品——而且作者越是想做大局面的关卡，它越难开门。

本文档解决三件事：

1. **主持人是什么** —— 它主持关卡、扮演主持人人格、制造氛围，但**永远不碰胜负判定**。
2. **AI 编号如何补位** —— 让一个人也能随时开局，并且这件事在世界观里完全成立。
3. **创作者生态如何运转** —— 从投稿、试跑、灰度、上架，到造关者的余命抽成与声望积累。

## 1. 核心原则：主持人不裁判胜负

### 1.1 职责边界

这是整套设计的地基，任何后续设计都不得动摇：

> **胜负、余命、出局、密令达成——全部由规则本身判定。**
> **主持人只负责开场叙事、氛围、演出，以及在模糊地带从有限选项中做出一次选择。**

| 事项 | 归属 | 说明 |
|---|---|---|
| 发牌与一切随机结果 | **规则** | 结果可复盘，任何人不得干预 |
| 合法行动集合的计算 | **规则** | 主持人无权扩展玩家能做什么 |
| 出局判定 | **规则** | 主持人说的任何一句话都不能直接让人出局 |
| 余命增减与结算 | **规则** | 唯一货币的账本必须闭环 |
| 密令达成判定 | **规则** | 密令目标必须是可被明确判定的结构，见 [03](03-mandate.md) |
| 回响激活条件检查 | **规则** | 见 [04](04-echo.md) |
| 压制的生效范围 | **规则** | 见 [07](07-level-design.md) |
| 规则修正件的执行与优先级 | **规则** | 冲突由既定顺序解决，不由主持人临场决定 |
| 开场旁白与规则宣读的措辞 | **主持人** | 纯表现，不改变规则语义 |
| 回合之间的气氛描写 | **主持人** | 纯表现 |
| 主持人的语气、称呼、态度 | **主持人** | 人格演出 |
| 对某编号行为的评论、挑拨、诱惑 | **主持人** | 影响玩家心理，不影响判定结果 |
| **模糊条款的裁决** | **混合** | 主持人从封闭候选中选一项，并公开写出理由 |
| **临场事件的投放** | **混合** | 主持人从白名单事件池中挑选并包装，规则负责执行 |
| **AI 编号的行动决策** | **混合** | 主持人给出意图，规则校验合法性，非法则回退 |

### 1.2 混合项的收口设计

混合项是唯一让主持人影响局面的通道，必须**结构化收口**。

**模糊条款裁决 —— 只能选，不能判**

1. 出现无法被规则自动判定的情形（例如作者写的密令文案与实际行动之间存在解释空间）。
2. 系统向主持人提出一个**封闭式问题**：给出中立的情境描述，以及**有限的候选裁决**（通常 2–4 个）。
3. 主持人**只能选择其中一个**，并写出理由。
4. 如果主持人选了候选之外的东西、或者迟迟不作答，则自动采用**预设默认选项**——默认永远取"对玩家有利"的那一个。
5. 裁决结果与理由**全场公开**。

> **关键设计约束：主持人从来不"自由裁决"，它只是在既定选项里挑一个，并给它一个说法。
> 它的自由度在措辞，不在结果。**

**临场事件 —— 只能从白名单里挑**

关卡包与基础玩法模板共同定义一个**事件白名单池**（例如"追加一轮发言""公开一条已弃置的信息""开放一次交换机会"）。每个事件都是已经过校验的既定效果。主持人的权力仅限于三点：

- 在允许的时机**是否**投放事件
- **投放哪一个**（从白名单中选）
- 用什么措辞包装它

事件本身的执行与后果完全由规则完成，且每局有投放次数上限，防止事件轰炸。

### 1.3 为什么这条边界必须存在

**理由一：让说服主持人不构成作弊。**

玩家一定会尝试忽悠主持人——在发言里夹带指令、编造"系统提示"、诱导它公开不该公开的东西。这类尝试**无法被彻底杜绝**，所以正确的做法不是防死它，而是让它**不重要**。

当主持人的最大权限只是"从候选里选一项并写一段话"时，成功忽悠它的最大收益，也不过是让主持人说了一段奇怪的话。而在一个由不可信的主持人掌管的诡异世界里，主持人说奇怪的话甚至算不上破绽。

**理由二：主持人失灵时，对局不能中断。**

主持人有可能沉默、跑题、答非所问，或者干脆不在。如果结算依赖它，一次异常就是一场 40 分钟对局的崩溃。

在当前设计下，主持人卡住的后果仅仅是"主持人沉默了一会儿"——回合照常推进，判定照常生效。

> **降级必须在叙事上被吸收，而不是弹出一句"服务不可用"。**
> 主持人忽然不说话了，只剩下冷冰冰的规则播报，在这个世界观里完全成立，**甚至更恐怖**。
> 玩家可以在事后查看本局主持人是否失灵过，但对局界面永远不弹任何报错。

**理由三：主持人的介入次数是可预期的。**

一局关卡里主持人需要开口的次数，是可以事先算出来的：开场一次、每回合至多一次、裁决按需、结算一次。介入次数可预期，才能保证节奏稳定、保证降级有兜底、也才能让"玩家接入自己的模型"这件事不至于失控。如果主持人参与结算，它的介入次数会随局面复杂度不可控地膨胀。

## 2. 谁来主持：外部模型接入

### 2.1 原始构想的保留

产品最初的构想之一是：**玩家可以接入自己的模型，来主持自己设计的关卡。**

这条必须保留，因为它是创作者表达的最后一环：

| 创作者能决定的 | 说明 |
|---|---|
| 关卡的规则 | 基础玩法模板 + 规则修正件 + 密令池 + 压制 |
| 关卡的**声音** | **由谁来主持、用什么人格、什么语气、说什么话** |

一个以假信息为核心的关卡，如果主持人的每句话都四平八稳，这个关卡就废了一半。**让创作者能亲手调教自己关卡的主持人，是 UGC 从"设计规则"升级为"创造体验"的关键。**

### 2.2 铁律：主持人是增强，不是门槛

> **任何编号，在没有接入任何外部模型的情况下，都必须能完整体验核心循环。**

这条不能妥协。理由很直接：如果没有模型就开不了局，那么"AI 编号补位解决开局人数门槛"这套设计的整条逻辑就断了——冷启动问题会原封不动地回来。

因此：

| 情形 | 表现 |
|---|---|
| 有创作者提供的主持人 | 完整的人格演出、临场评论、个性化裁决陈词 |
| 无外部模型 | 主持人使用关卡上架时预先备好的台词，人格依然在，只是不会临场应变 |
| 台词也不适用 | 通用的主持人措辞 |
| 全部不可用 | **静默主持**：只保留规则播报——沉默的主持人，本身就是一种演出 |

四种情形下，**规则、判定、余命、密令、回响完全一致**。差别只在氛围浓度，不在公平性，也不在能不能玩。

### 2.3 主持人可以看到什么

**主持人只能看到"它作为主持人有权看到的东西"。**

绝不能把全场的隐藏信息都摊给主持人，然后指望它"知道但不说出来"——那是把保密性寄托在演员的自律上。主持人拿到的情境，必须是已经按可见性裁剪过的版本。

这不只是安全考量，也是叙事设定：**主持人是规则的化身，不是全知的神。** 有些事它也不知道，这让它更像一个角色，而不是一个后台。

## 3. AI 编号：补位是设定，不是妥协

### 3.1 定位

关卡要几个人由作者说了算，多数关卡在 8 人以上。真人凑不齐时，由**终焉之地的居民**入场补位——这就是 AI 编号。

这一点在世界观上**完全自洽**：终焉之地里本就有大量身份不明、来历不明、在无数轮回中反复出现的编号。玩家遇到一个沉默寡言、行为诡异的同伴，不会觉得"这是个凑数的机器人"，只会觉得"这地方本来就有这样的人"。

> **AI 编号不是降级体验，它是这个世界的居民。**

它直接解决三件事：

| 问题 | 解法 |
|---|---|
| 冷启动凑不齐关卡要求的人数 | 随时可开局 |
| 冷门时段、冷门关卡无人问津 | 长尾关卡依然可玩 |
| 真人中途掉线 | 无缝接管，对局不崩 |

### 3.2 人格的设计维度

每个 AI 编号入场时都会拿到一份人格设定。它不是一堆参数，而是**一个能被玩家记住的人**。

需要被设定的维度有这些：

| 维度 | 它决定了什么 | 举例 |
|---|---|---|
| **底色** | 这个人的基本性格 | 谨慎、冲动、谄媚、冷漠、表演型 |
| **话密度** | 它多爱说话 | 沉默寡言 / 适中 / 话痨 |
| **信任倾向** | 它一开始信不信别人，以及信任崩塌的速度 | 一开始就谁都不信，且几乎不会回头 |
| **诚实倾向** | 它撒不撒谎，以及撒谎的风格 | 常撒小谎，但不擅长圆谎 |
| **虚构前史** | 一段编造的过去，让它的行为有连贯动机 | 曾被同伴推出去顶罪 |
| **口癖** | 少量语言习惯，制造辨识度 | 句尾常带"……大概吧" |
| **能力档位** | 它有多强，见 §3.4 | 中 |

**虚构前史**是最重要的一项。它不需要真实，但它必须**一致**——一个"曾被同伴顶罪"的编号，在被要求结盟时会犹豫，在有人提出集体投票时会格外抗拒。玩家未必能说清它为什么怪，但会感觉到它有自己的来历。

人格在**整局内保持一致**，并在对局档案中留存，用于事后复盘。

### 3.3 让它像人一样执行密令

AI 编号和真人一样，**从密令池中抽取密令**，并且必须真的去执行。

这是它们产生"人味"的关键：**人的怪异行为往往源于我们看不见的动机**，而密令恰好提供了这种隐藏动机。一个 AI 编号莫名其妙地保护某个玩家、莫名其妙地不肯加注，玩家的第一反应不会是"它坏了"，而是"它想干什么"。

**刻意保留的不完美：**

不要求 AI 编号最优执行密令。它**可以执行失败、可以被识破、可以在压力下改口、可以放弃**。

> 一个从不失误的 AI，第一局就会暴露。

### 3.4 能力必须弱于人类玩家

> **硬性原则：AI 编号的能力上限必须低于同层人类玩家的平均水平。**

理由：AI 编号存在的目的是"让局开起来"，不是"提供挑战"。一个能稳定读牌、精确计算、永不失误的 AI，会把关卡变成人机对抗，摧毁社交博弈的乐趣。

| 档位 | 适用日层 | 特征 |
|---|---|---|
| **弱** | 试炼层（1–3 日） | 明显的失误、容易被说服、几乎不主动结盟 |
| **中** | 倾轧层（4–6 日） | 会结盟、会背叛，但算得很粗糙 |
| **强** | 崩坏层（7–9 日） | 有策略连贯性，能记住整局的承诺与违约，但仍不做精确计算 |

**明确禁止的能力：**

- 不得看到任何超出其可见范围的信息——与真人完全一致的裁剪
- 不得进行超出人类可行范围的精确计算
- 不得拥有回响（见 §3.6）
- 不得跨局记忆（"反复出现的叙事 NPC"属于剧情内容，不属于补位系统）

### 3.5 破绽与对策

真人识破 AI 最常见的破绽，以及对应处理：

| 破绽 | 对策 |
|---|---|
| **回复太快** | 按发言长度模拟思考与打字的时间，并加入随机抖动；重要发言前刻意停顿 |
| **句式太整齐、太书面** | 强制口语化，允许省略、允许说半句、允许打错字；限制单次发言长度 |
| **永远接话** | 按话密度**概率性地主动放弃发言**；即使被点名也有概率沉默 |
| **从不改口** | 允许并鼓励中途改变立场，尤其是在被质疑之后 |
| **情绪恒定** | 信任度随局内事件变化，并反映在措辞上 |
| **从不犯规则错误** | 允许它低概率地提出不合法的行动，被驳回后"道歉改口"——**这是极强的拟人信号** |

### 3.6 AI 编号与回响

**AI 编号不拥有回响。**

理由：回响的来源是角色过去的**真实经历与执念**，而 AI 编号没有跨轮回的人生。给它们回响，既在设定上说不通，又会稀释"回响是稀有的、属于你的东西"这一核心价值。

例外：**叙事性 NPC**（官方手工设计、在多个轮回中反复出现、承担剧情功能的特定编号）可以拥有回响，但那属于剧情内容，不属于补位系统。

> **注意**：这条与"不告知玩家谁是 AI"存在张力——如果只有 AI 从不在轮回内激活回响，玩家就能反推。
> 见 §8 未决问题第 1 条。

### 3.7 是否告知玩家谁是 AI

**建议：不告知个体。**

| | 不告知（建议） | 告知 |
|---|---|---|
| **氛围** | 强。"你旁边这个到底是不是人"本身就是终焉之地的恐怖来源 | 弱。AI 变成明确的背景板 |
| **猜疑链** | 强化。识破 AI 成为一项玩家技能，而且**会误伤真人** | 削弱。玩家只在真人之间博弈 |
| **社交伤害** | 有风险。真人被误认为 AI 而遭无视、被优先淘汰 | 无 |
| **信任成本** | 高。玩家可能怀疑"我是不是被塞进了一屋子机器人" | 低 |
| **匹配自由度** | 高。可随时补位 | 低。玩家会拒绝进 AI 多的房 |

**折中方案（推荐落地）：**

1. **不标记个体**，但**公示总量区间**——房间信息显示"本局真人 7–9 名"，给一个带模糊度的区间而非精确数字。
2. 玩家可在匹配设置里选择**"仅真人房"**，代价是排队时间显著变长。把选择权交给玩家，同时让绝大多数人在"体验"与"等待"之间自然选择前者。
3. **对局结束后的档案中如实披露**谁是 AI 编号。既满足好奇心、维护长期信任，又不破坏局内的猜疑体验。

## 4. 主持人

### 4.1 定位与双重约束

主持人是**关卡的主持者与规则的化身**，不是对抗方。当造关者本人不在场时（绝大多数情况），由主持人扮演该关卡指定的人格。

它受两重约束：

1. **裁量约束**：主持人的裁量范围，由**关卡在上架时声明的裁量清单**限定——清单逐条写明它可以就哪些事项裁量、裁量能触及的最高效果层级（L1 影响信息 / L2 影响判定 / L3 影响规则 / L4 影响他人）。**超出清单即越权。**
2. **规则约束**：一切"权力"最终都必须落到既定的白名单效果上（见 §1.2）。

### 4.2 人格的设计维度

主持人人格由造关者设定，需要被决定的是这些：

| 维度 | 它决定了什么 |
|---|---|
| **裁量范围** | 它能就哪些事项裁量、最高触及哪个效果层级，必须与关卡声明的裁量清单一致 |
| **称谓** | 玩家怎么称呼它，它怎么称呼玩家（"编号 043" / "小家伙" / "各位来宾"） |
| **语气** | 冷峻 / 戏谑 / 悲悯 / 狂热 / 官僚 / 温柔 |
| **话量** | 惜字如金 / 适中 / 喋喋不休 |
| **立场** | 它对编号的基本态度：中立 / 挑拨 / 引导 / 冷眼旁观 |
| **口癖** | 至多三条，用于强化辨识度 |
| **背景素材** | 作者提供的一段世界观描写，供开场旁白取材 |
| **介入额度** | 本局它最多能投放几次临场事件 |
| **备用台词** | 主持人失灵时使用的预备台词，由作者确认 |

**一条硬性约束：背景素材与口癖里不得包含任何规则性表述。**

不能出现"本关中弃权者将被扣除余命"这类句子。规则只能来自规则修正件，不能来自旁白。

> 否则玩家将无法区分"这是规则"还是"这是演出"，**公平感会立刻崩塌**。

### 4.3 裁决记录：把主持人置于监督之下

主持人的每一次裁量，都必须留下**全场可见的裁决记录**：

| 记录项 | 内容 |
|---|---|
| **时刻** | 第几回合、哪个阶段 |
| **争议** | 中立的情境描述 |
| **候选** | **本次可选的全部裁决，包括未被选中的那些** |
| **裁决** | 主持人选了哪一项 |
| **理由** | 主持人的陈词 |
| **依据条款** | 本次裁量依据的是裁量清单中的哪一条 |
| **影响** | 实际发生了什么 |

> **公开全部候选项是这里最关键的设计。**
> 它让玩家看到"本来还可以怎么判"，从而能自行判断这次裁决是否偏袒。

这些记录同时是造关者声望与**主持人申诉、褫夺机制的证据来源**（见 [05](05-authority-and-ascension.md)）。没有它，权力枷锁就是一句空话。

### 4.4 有人试图说服主持人时

即便主持人不判胜负，被玩家"说服"依然会破坏体验——比如被诱导着公开某个编号的隐藏信息。设计层的护栏有三道：

| 护栏 | 内容 |
|---|---|
| **它根本不知道** | 主持人拿到的情境已按可见性裁剪。**它说不出它不知道的东西**——这是最有效的一道，其余两道只是补充 |
| **它只能在裁量清单内裁量** | 超出关卡声明清单的裁量一律无效，且**越权行为本身会被记入裁决记录**，成为申诉证据 |
| **世界观兜底** | 见下 |

**最后一道防线写在设定里：主持人本就是不可信的。**

主持人会戏弄编号、会看热闹，它甚至可能以误导为乐。玩家从进入终焉之地的第一天起就被教育：**主持人说的话从来不保证为真，只有规则播报才是真的。**

于是，即使有人成功忽悠了主持人，最坏后果也只是"主持人说了句不该说的话"——而这在设定里根本不是异常，是它的常态。

> 我们把主持人天然不可靠这件事，直接写进了世界观。这不是掩饰，是把风险转化为氛围。

## 5. 创作者生态

### 5.1 谁可以投稿：所有人

> **造关是通用能力，没有身份门槛。任何玩家，任何时候，付得起余命就能创建关卡并主持它。**
> 完整论证见 [05 §5.1](05-authority-and-ascension.md)；本节只写流程。

| 项 | 规定 |
|---|---|
| 谁能投稿 | **所有编号**。不看回响阶数、轮回次数、前史完整度、造关者声望 |
| 成本 | **买地**（大额）+ 地块维护费（周期性）+ 每场开局的奖池垫付，**只收余命**（[07 §4](07-level-design.md)、[02 §2.3](02-economy-lifespan-memory.md)） |
| 硬约束 | 作者**不得以编号身份参与自己创建的关卡**（[05 §5.2](05-authority-and-ascension.md)） |
| 把关的是什么 | **关卡的质量，不是作者的资历**——下面这条流水线筛的每一道，筛的都是内容 |

### 5.2 投稿流程

```
买地                 大世界里选一块地并付余命（[07 §4](07-level-design.md)）
  ↓                  没有地就打不开编辑器
草稿（关卡编辑器）
  → 自动校验          能不能跑通、有没有死锁
  → 用 AI 编号试跑     客观质量画像，不需要真人
  → 沙盒房            作者与好友，不结算余命
  → 灰度池            少量自愿真人，余命波动减半
  → 正式池
  → 持续监控 / 版本迭代 / 必要时下架
```

**买地是唯一的前置条件，之后的每一道都只筛内容。** 作者在编辑器中全程可见校验报告与试跑统计，**每一次失败都附带具体原因与可回看的失败样本**。

> **编辑器本身就是最重要的创作者教育工具。** 它不该只是一个提交入口，而应该在作者犯错的当下就告诉他为什么。

### 5.3 造关者的余命抽成

**造关者从自己关卡的每一局对局中抽取余命。** 这是 UGC 生态的经济引擎。

| 项 | 设计 |
|---|---|
| **抽成来源** | 从本局余命**流转总额**中抽取，**不是从输家身上额外扣** |
| **比例上限** | 平台设硬上限（建议 3%–8% 区间），由作者在上限内声明 |
| **质量挂钩** | 实际到手 = 声明比例 × 质量系数。**劣质关卡即使声明高抽成也拿不到多少** |
| **灰度期** | 灰度期不抽成或半额抽成，防止刷灰度收益 |
| **结算周期** | 按轮回结算、延迟到账，给举报与复审留出窗口 |
| **冻结** | 确认存在漏洞利用或抄袭时，冻结并追回该关卡产生的全部抽成 |

**设计意图**：让"做一个好关卡"成为一条**可持续的生存方式**。

一个不擅长博弈、但擅长设计的玩家，可以靠造关养活自己的余命，从而长期留在终焉之地。这为非战斗型玩家提供了完整的生态位——而这类玩家恰恰是内容供给的命脉。

### 5.4 造关者声望：独立的第二条声望轴

造关者声望与玩家战绩声望**完全独立，互不换算**。

| 维度 | 玩家声望 | 造关者声望 |
|---|---|---|
| 来源 | 生还、密令达成、守约 | 关卡的公平与张力评分、稳定运行、被收录 |
| 展示 | 编号档案页 | 关卡署名、造关者名录 |
| 用途 | 社交信任、匹配分层 | 推荐权重、征稿资格、抽成上限 |
| 惩罚 | 违约、恶意行为 | 抄袭、漏洞利用、刷量 |

> **造关者声望不是一道门槛，是一份履历。**
> 它不决定你能不能造关（**任何人付得起余命就能造**，见 [05 §5.1](05-authority-and-ascension.md)），
> 只决定你的关卡被多少人看见、能抽多少成、能不能进征稿。
> 一个零声望的新人和一个高声望的老作者，**上架的权利完全相同，起跑的曝光不同**。

### 5.5 经典关卡库

评分与运行数据长期稳定在高位的关卡，被收录进**经典关卡库**：

- 永久保留，不受推荐轮换影响
- 作者获得永久署名与荣誉标记
- 成为新造关者的公开学习范本——**可以查看它的完整配置，作为教学案例**
- 定期在「大终焉」中被重新启用

### 5.6 赛季主题征稿

每个赛季设定一个主题，围绕该主题征稿，例如「**改写规则的人**」「**说谎者**」。

- 主题期内，与该主题相关的规则修正件库开放额外条目
- 入选作品获得推荐位与额外抽成加成
- 优胜者获得**长期推荐位与永久署名**
- 主题为内容运营提供了天然节奏，也让不同玩法风格轮流登场

### 5.7 抄袭与举报

| 情形 | 处理 |
|---|---|
| **配置雷同** | 对关卡的结构（模板 + 修正件集合 + 参数）做相似度比对，高度雷同者自动标记，先到者优先 |
| **文案抄袭** | 相似度检测 + 人工复审 |
| **致敬 / 改编** | **允许**，但必须声明来源，且抽成需与原作者分配——提供正式的"衍生作品"通道 |
| **漏洞利用** | 立即下架、冻结抽成、造关者声望重罚 |
| **恶意举报** | 记录举报者信誉；反复恶意举报者限制举报权 |

## 6. 质量漏斗

### 6.1 UGC 平台只有两种死法

**没人投稿**，或者**好东西沉底**。质量漏斗必须同时解决这两件事。

### 6.2 冷启动一个新关卡

新关卡最大的困难是：**没有样本就没有评分，没有评分就没有曝光。**

解法是让漏斗的前段**完全不依赖真人**：

| 阶段 | 样本来源 | 玩家成本 | 产出 |
|---|---|---|---|
| 自动校验 | 无 | 无 | 能不能跑 |
| **用 AI 编号试跑** | AI 编号 | 无 | **致死率、单局时长、密令达成率、决策分散度** |
| 沙盒房 | 作者与好友 | 不结算余命 | 主观手感 |
| 灰度池 | 少量自愿真人 | 余命波动减半 | 首批真人评分 |
| 正式池 | 全量 | 正常 | 持续统计 |

> **AI 编号试跑是整个漏斗的关键杠杆**：它让一个零曝光的新关卡，在见到第一个真人之前，
> 就已经拥有了一份客观的质量画像。推荐可以据此给出**初始曝光**，
> 而不是让新关卡在零信息状态下饿死。

### 6.3 让好关卡浮上来

推荐权重的构成倾向：

| 因子 | 权重 | 说明 |
|---|---|---|
| **公平评分** | 最高 | 低公平分直接压制曝光，接近一票否决 |
| **张力评分** | 高 | 核心体验指标 |
| **完成率** | 中 | 中途退出率高说明体验有问题 |
| **试跑指标健康度** | 中 | 客观、抗刷 |
| **新鲜度衰减** | 中 | 防止头部关卡永久霸榜 |
| **多样性配额** | 中 | 保证各类玩法风格、各日层、各人数区间都有曝光 |
| **游玩次数** | **最低** | **刻意压低** |

**刻意压低"游玩次数"是一个明确的设计选择。**

热度驱动的推荐会迅速让平台被少数几个关卡垄断，而本作需要的是**长尾丰富度**——玩家在一个轮回里要连打 10 个关卡，重复会极快地消耗新鲜感。宁可牺牲一部分"爆款效应"，也要保住关卡池的宽度。

### 6.4 防刷量

| 手段 | 说明 |
|---|---|
| **AI 局不计入热度** | AI 编号占比过高的对局，其评分与热度按真人比例折算 |
| **同伙检测** | 作者与固定小圈子反复对局的样本降权 |
| **余命成本锚定** | 有效样本必须是真实结算过余命的对局——**刷量有真实成本** |
| **评分资格** | 〔待定〕口径取决于 [06](06-death-and-recurrence.md)：出局者是否留在局内、是否有资格评分 |
| **异常分布告警** | 评分分布异常（全五星、集中在同一时段）触发人工复审 |

## 7. 一句话总结

| 角色 | 它能做什么 | 它绝不能做什么 |
|---|---|---|
| **规则** | 决定一切胜负、余命、出局、达成 | —— |
| **主持人** | 叙事、氛围、演出、从封闭候选中选一项并说明理由 | 决定任何人的死活 |
| **AI 编号** | 补位、执行密令、像人一样犯错 | 强于真人、看到不该看的、拥有回响 |
| **造关者** | 设计规则、设计密令、设计主持人的声音 | 在自己的关卡里获得对局优势 |

## 8. 未决问题

1. **AI 编号究竟有没有回响？**
   本文档写的是"不得拥有"，但这与"不告知玩家谁是 AI"直接冲突——如果只有 AI 从不在轮回内激活，玩家可以用"谁从没激活过"反推身份。二者必须一起拍板。倾向的折中是：AI 编号可以使用 0–1 阶回响形状，其"前史"由官方预设，不积累渴望、不分化，每轮回仍需重新激活。

2. **AI 编号在一局里的占比上限定多少？**
   暂定 50%。太低则冷启动无效，太高则玩家会认为"这就是个单机游戏"。与第 1 条强耦合，建议合并决策。

3. **是否告知玩家谁是 AI？**
   本文推荐"不标记个体 + 公示总量区间 + 局后档案披露"。但依然存在真人被误认为 AI 而遭社交排斥的风险；而一旦玩家群体普遍认为"房里都是机器人"，口碑会迅速崩塌。建议在灰度期用真实数据验证。

4. **造关者抽成的比例区间与质量系数曲线如何定？**
   抽成太低则无人创作，太高则玩家不愿进 UGC 关卡（"进去就被抽血"）。质量系数又要在"鼓励新人"与"防止劣质关卡吸血"之间取平衡。这直接关系到 UGC 生态能否自持。

5. **没有外部模型的关卡，体验落差有多大？**
   我们声称主持人是增强而非门槛，但如果备用台词明显更差，就会形成事实上的体验分层（能接入模型的人玩得更爽）。备用台词要备到多丰富，才能让落差小到可以接受？这份内容由谁来生产？

6. **主持人是否应该拥有跨局记忆？**
   目前 AI 编号不跨局记忆。但主持人作为某个关卡的固定角色，如果能记住"上次来过的编号"，会极大增强终焉之地的宿命感——"你又来了"这四个字的分量非常重。风险是跨局的信息泄露与叙事一致性维护。价值很高，需单独评估。

7. **AI 编号的能力档位是否对玩家公示？**
   公示能让玩家理解"为什么这个 AI 这么蠢"，但也会破坏"分不清谁是 AI"的氛围。若不公示，弱档位 AI 的低质量决策可能被误认为是真人在划水，引发举报与冲突。

8. **需要防止有人把关卡当作免费的模型代理使用。**
   例如创建一个没有真实玩家的关卡，通过密令文案或发言诱导主持人持续输出与游戏无关的内容。设计上的应对方向是：主持人的发言天然简短、任务类型封闭、且长期无人参与、无余命流转的关卡应当被冻结。具体策略待定。
