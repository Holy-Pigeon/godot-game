# 10 · GM 与设计验证

> 状态：验证规格 v0.3 ｜ 真源：无需长线刷局的验证能力

## 原则

长期系统不能靠真实打数十轮验证。GM 必须能直接设置状态、跳转流程并记录事件，且 GM 行为不能污染正式经济或档案。

## 可直接设置的状态

| 范围 | 状态 |
|---|---|
| 身份/前史 | 编号、前史碎片、执念格、关系、渴望值、回响形状与阶数 |
| 回响 | 每条激活谓词、激活状态、燃料、压制、首次“觉醒”演出 |
| 关卡 | 模板、修正件、谓词、密令、余命、公开/隐藏事件、流程阶段 |
| 对局 | 真人/AI 构成、人格档、人数、随机种子、裁量清单 |
| 记录与推断 | 查看任意一局的规则事件流与行为语料流、该局产出的执念倾向增量及其引用证据；可关闭推断管线，见 [13](13-record-and-inference.md) |

## 三个必测场景

| 场景 | 操作 | 验收 |
|---|---|---|
| 回响手感 | 设定形状与条款 → 激活 → 放弃 → 发动 → 进入下一轮回 | 激活不自动生效；放弃无成本；发动有燃料/暴露；下轮回重置 |
| 前史归还 | 改变行为记录与碎片顺序 | 前史、执念和生成形状能被解释且可复盘 |
| 关卡人格采样 | 跳转到关键回合，替换真人/AI与密令组合 | 模板能制造分歧、密令可达成、AI 不破坏规则 |

## 约束与输出

- GM 数据必须隔离于正式余命、收成、推荐与玩家档案。
- 每次验证导出状态快照、事件日志、随机种子和版本号。
- 无法从 GM 复现的设计结论，不得视为已验证。
- 复算只允许使用规则事件流。删除行为语料流后，余命、承担值、奖励、失守与完美判定必须完全一致；推断产出只作为快照留存，不进入验收复算。
