# 10 · GM 模式与设计验证

> 状态：草案 v0.1 ｜ 关联：[索引](README.md)、[04 回响](04-echo.md)、[03 密令](03-mandate.md)、[07 关卡设计](07-level-design.md)
>
> 本文档只讨论**设计侧的验证需求**：我们需要能直接设定什么状态，才能把设计验完。
> 不讨论任何技术实现。

---

## 1. 为什么必须有 GM 模式

本作的三条长期轴——生存、真相、权柄——**全部是跨轮回累积的**：

```
打若干局 → 行为被观测 → 前史归还 → 执念成型 → 渴望值累积 → 遇到共振情境 → 觉醒回响
```

按 [04 §9.1](04-echo.md) 的稀有度目标，2 阶回响的预期达成时间是**第 10–20 轮回**，
3 阶是**数十轮回 + 极端自律**。

> **如果验证一次"3 阶回响手感对不对"要先真打几百局，这个设计就没法迭代。**

这不是效率问题，是**可行性问题**。没有 GM 模式，长期轴的所有设计都只能靠想象，
上线后才发现手感不对，那时已经来不及改。

**结论：GM 模式是设计验证的一等公民，与关卡本身同等重要（[D-14](README.md)）。**

---

## 2. 必须可以被直接设定的状态

按"验证哪条设计"分组。凡是**需要靠时间累积才能到达的状态**，都必须能被直接设定。

### 2.1 身份与前史

| 可设定项 | 用来验证 |
|---|---|
| 前史找回度（0–100%） | 觉醒三重合取的第 ① 条 |
| 已归还的记忆碎片及其**解读选项**（那天我恨他 / 我原谅了他 / 我什么都没想） | 玩家的作者权是否真的改变了执念走向 |
| 执念格（W1–W8 × R1–R4，共 32 格） | 同一格的两个人，回响是否真的长得不一样 |
| 归属权柄系 | 矩阵映射是否合理 |

### 2.2 回响

| 可设定项 | 用来验证 |
|---|---|
| 持有的回响及其**阶** | 各阶手感、暴露机制的心理压力 |
| 触发条件的每一条条款（可单独置为"已满足"） | 苛刻度换算是否合理；**共鸣类是否真的让人觉得"这是我的过去在回答我"** |
| 语义锚点（动词 + 作用对象 + 层级） | [04 §7.5](04-echo.md) 的跨模板映射是否成立 |
| 渴望值 | 觉醒阈值、反自残刷值判定 |
| 强制触发一次觉醒演出 | 新人首次濒死的高光时刻（[04 §9.2](04-echo.md)） |

### 2.3 关卡内

| 可设定项 | 用来验证 |
|---|---|
| 指定某人拿到指定密令 | 冲突图、密令达成率、结算揭晓的震撼度 |
| 强制推进/回退阶段，跳过回合 | 张力曲线的分段验证，不必每次打满全程 |
| 直接改写任一编号的余命 | 绝境触发点、生死线的心理压力 |
| 临时开关压制 | 绝缘区的恐怖感是否成立 |
| 让指定编号出局 / 复活 | 观测者态、刻印、连锁反应 |

### 2.4 对局构成

| 可设定项 | 用来验证 |
|---|---|
| 人数（4–16）与 AI 编号占比 | 三个规模档（密室 / 主流 / 舆论）的体验差异 |
| AI 编号的人格与能力档位 | 补位是否真的"像这个世界的居民" |
| 全部由 AI 编号构成的空跑局 | 关卡流程能否自洽跑完，无需真人 |

> **最后一条是 MVP 阶段最省时间的能力**：一个人 + 一屋子 AI 编号，就能把一张新关卡跑通。

## 3. 三个必须支持的验证场景

### 场景 A · 回响手感验证（最常用）

```
设定：执念格 + 回响 + 阶 + 触发条款全部置为已满足
进入：任意关卡
观察：发动时全场的反应、暴露之后的社交后果、烧掉记忆的心疼程度
```

要回答的问题不是"数值平不平衡"，而是——
**发动的那一刻，玩家会不会觉得"这是我的过去在替我出手"？** 这一条不成立，回响系统就是失败的。

### 场景 B · 前史归还验证

```
设定：一段虚构的行为历史（如"连续 5 局背叛盟友"）
观察：系统还给他的是不是"你曾被最亲的人背叛"
     以及玩家看到这段过去时的反应
```

这条链最怕的失败是**玩家觉得系统在指责他**。归还的过去必须让人觉得"原来如此"，
而不是"凭什么说我是这种人"。

### 场景 C · 关卡决策的性格采样验证

```
设定：同一张关卡，让若干个不同人格的 AI 编号跑完
观察：他们的决策序列能否被系统正确归类到不同的 W×R 格
```

这是**样板关卡是否合格的判据**：如果四种人格跑完落在同一格，
说明这张关卡的决策点全是数值题，读不出性格，必须重做。

## 4. 约束

| 约束 | 说明 |
|---|---|
| **GM 模式不得进入正式对局** | 一旦玩家能设定自己的回响阶数，整套稀有度与自律设计当场作废 |
| **GM 修改必须留痕** | 验证局的所有数据要能与正式局区分，否则会污染健康度指标 |
| **GM 不得成为运营的常规手段** | 用它救急（补偿玩家）是可以的，用它给特定玩家开小灶就是舞弊，需审计 |
| **GM 不改变判定逻辑** | 它只设定**状态**，不改变规则如何裁决。否则验证的就不是真实系统 |

## 5. 未决问题

1. **GM 模式要不要向创作者开放？** 关卡作者显然需要它来调自己的关（否则他也要真打几十局），
   但开放给作者就等于开放给一大批人，滥用面积会变大。
   **倾向**：作者只能在**自己的关卡的试跑沙盒**里用，且沙盒局不产出任何余命与记忆碎片。
2. **AI 编号能否被赋予指定的执念格？** 场景 C 依赖这一条。
   但让 AI 扮演一种执念，与让它扮演一种性格是两回事，前者要求它的**决策序列**可归类，不只是说话风格。
3. **验证局的数据能否用于标定参数？** AI 编号的行为分布未必等于真人，用它标定苛刻度权重可能系统性偏差。
   **倾向**：AI 空跑只用于验证"流程能不能跑通""决策能不能被归类"，**不用于标数值**。
