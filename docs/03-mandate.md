# 03 · 密令系统

> 状态：核心规格 v0.3 ｜ 真源：私人目标、判定与分配

## 定义与原则

每名编号在关卡中持有一条只对自己可见的密令。密令不等于阵营：它让同一桌人拥有相互冲突、可合作但无法完全对齐的收益。

- 判定只引用可复盘的结构化事件，不判断意图或聊天语气。
- 自然语言只用于展示；结算使用字段与事件日志。
- 优先使用完成度而非纯成败，避免提前失败后彻底摆烂。
- 结算公开口径待定；持有者的实时进度仅自己可见。

## 最小规格

```text
mandate_id / 分类 / 标题与展示文案 / 目标选择器 / 目标解析时机
成功与失败条件 / 判定时机 / 完成度模型 / 奖励与记忆产出
失败渴望值 / 泄露策略与惩罚 / 冲突标签 / 难度 / 发放时机
```

生命周期：**抽取 → 发放 → 目标解析 → 事件推进 → 提前判负（如有）→ 结算 → 按规则公示**。

## 六类密令

| 类别 | 目标 | 与其他系统的关系 |
|---|---|---|
| 猎杀 | 促成指定对象损失、出局或失败 | 制造公开敌意 |
| 守护 | 保住对象或结果 | 失败可提供无力类渴望 |
| 约束 | 自己不得做某事 | 与禁忌类回响条件同构 |
| 操纵 | 改变他人选择或关系 | 制造言行不一线索 |
| 信息 | 获取、保守或误导信息 | 以记忆奖励为主 |
| 自毁 / 献祭 | 用自身利益换取特定结果 | 制造极端选择 |

复合密令属于后续内容；MVP 先验证单一、可读、可达成的密令。

## 分配与反作弊

- 按冲突标签生成组合，避免全场目标同向或无解。
- 分配前执行可达性校验；动态目标可在指定时机再解析。
- 不提供系统级的口头自证；不可告知密令只能通过结构化“出示”触发泄露惩罚。
- 开黑缓解：延迟发放、动态目标、诱饵密令、AI 补位和行为异常检测。

## 接口

密令为余命与记忆提供结算，为回响提供渴望事件和可判定情境，为关卡包提供冲突图与事件日志输入。具体未定项见 [09](09-open-questions.md)。
