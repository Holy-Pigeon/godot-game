## 1. 设计意图

### 1.1 密令要解决的问题

关卡的**基础玩法模板**（德州、投票放逐、拍卖、囚徒困境网格……）本身是成熟且平庸的。如果十个编号坐在同一张牌桌上，共享同一个胜利条件，那么终焉之地就只是一个换了皮的棋牌室。

**密令（Mandate）是把平庸玩法转化为社交推理的核心发明：**

> 每个编号在关卡开始时，除公开规则外，私下获得一条只有自己可见的隐藏目标。
>
> **同一张牌桌上，坐着几个人，就有几个不同的游戏在进行。**

于是德州不再是德州：
- 3 号在打德州。
- 7 号在努力让 3 号出局，牌怎么打不重要。
- 5 号必须全程不加注一次并活到最后，所以他的每一次弃牌都在说谎。
- 9 号的目标是保护 3 号，即使自己出局也算完成——他会为了一个陌生人送命，而 3 号永远不会知道为什么。

**公开规则由关卡规则冷酷裁决，密令负责生产叙事、结盟、背叛与猜疑。**

### 1.2 为什么密令替代了"阵营"

已锁定的方向是：普通编号**没有阵营**。原因在于阵营会杀死猜疑链——一旦玩家被告知"我们是人类阵营"，他们的第一反应会是集体协商、集体投票、集体对抗，而所有的私人算计都会被"团队最优解"碾平。

密令做的事情正好相反：

| | 阵营 | 密令 |
|---|---|---|
| 胜利条件数量 | 2 个（共享） | N 个（每人一个） |
| 玩家第一反应 | "我们该怎么办" | "他为什么要这么说" |
| 结盟性质 | 先天的、公开的 | 后天的、临时的、随时可背叛 |
| 信息结构 | 阵营内透明 | **全员互相不透明** |
| 背叛的可能性 | 需要额外设计内鬼机制 | 内建，无需额外机制 |

密令还有一个阵营给不了的东西：**它让"输"变得有价值**。自毁型密令的持有者会主动求死并因此获得大量余命——见[余命与记忆经济](./02-economy-lifespan-memory.md)的双池结算模型。**你无法通过筹码多少判断谁在赢，这是本作最核心的信息不对称。**

## 2. 密令的结构化定义

一条密令 = **目标类型 + 目标对象 + 达成判定 + 奖励 + 泄露惩罚**。

为了能被无歧义地裁决，密令的达成条件必须完全结构化，不允许出现需要人工解释的自然语言条件（自然语言只用于**呈现**给玩家的描述文案）。

### 2.1 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| `mandate_id` | 标识 | 密令唯一标识 |
| `category` | 枚举 | 六大分类之一：猎杀 / 守护 / 约束 / 操纵 / 信息 / 自毁 |
| `source` | 枚举 | 官方密令池 / 关卡包作者自定义 / 生肖临场追加 |
| `title` | 文本 | 呈现给玩家的标题，允许有叙事色彩 |
| `description` | 文本 | 呈现文案。**不参与判定** |
| `target_selector` | 选择器 | 目标对象的描述方式：指定编号 / 角色位次 / 条件匹配（"筹码最多者"）/ 无对象 |
| `target_resolve_time` | 枚举 | 目标何时确定：开局锁定 / 首次判定时动态解析 / 每回合重解析 |
| `success_conditions` | 条件组 | 达成判定的条件合取式，全部引用关卡内发生的公开事件 |
| `failure_conditions` | 条件组 | 提前判负的条件（如守护对象已出局） |
| `evaluation_timing` | 枚举 | 判定时机：即时 / 回合末 / 关卡结算时 |
| `completion_model` | 枚举 | 完成度模型：二值（成/败）/ 分级（0–3 档）/ 连续（0–100%） |
| `reward_weight` | 数值 | 参与密令分配池的权重，与难度正相关 |
| `memory_reward` | 数值 | 额外的记忆碎片产出（信息型密令常用） |
| `desire_on_failure` | 数值 | 失败时产生的渴望值，接入[回响系统](./04-echo.md) |
| `leak_penalty` | 结构 | 泄露惩罚：类型（作废 / 减成 / 反转 / 无）+ 数值 |
| `disclosure_policy` | 枚举 | 可告知性：可自由公开 / 公开需付代价 / **不可告知**（说出即触发泄露惩罚） |
| `conflict_tags` | 标签组 | 用于分配算法计算冲突度（如 `杀:3号`、`保:3号`、`禁:加注`） |
| `difficulty_tier` | 枚举 | 难度档，影响分配与配平 |
| `visibility_state` | 运行时枚举 | 私密 / 已自曝 / 已被证实 / 已被误指 |
| `deal_time` | 枚举 | 发放时机：开局 / 第 N 回合 / 特定事件触发 |

### 2.2 判定原则

1. **只引用公开事件。** 所有 `success_conditions` 必须建立在关卡内真实发生过、且事后可复盘的事件之上（某编号出局、某次投票、某次加注、某条信息被读取）。禁止依赖"意图"或"态度"这类无法裁决的概念。
2. **可复盘。** 每条密令的判定过程写入对局事件日志，结算后对全场公开（包括未达成的），这是关卡结束后最强的叙事高潮——**真相揭晓时刻**。
3. **完成度而非成败。** 优先使用分级或连续完成度模型，让"差一点"也有回报，避免玩家在明知失败后彻底摆烂（这同时是意识涣散判定的输入）。

### 2.3 密令的生命周期

一条密令在一局关卡内会经历固定的状态流转，判定与结算按此推进：

| 阶段 | 触发时机 | 系统行为 |
|---|---|---|
| **抽取** | 开局前，分配算法运行 | 从密令池中按冲突图约束选出全场组合，通过可达性校验 |
| **发放** | `deal_time` 到达 | 仅向持有者下发呈现所需的最小信息 |
| **解析** | `target_resolve_time` 到达 | 确定 `target_selector` 指向的具体对象 |
| **推进** | 每次相关公开事件发生 | 更新完成度，写入事件日志 |
| **提前判负** | `failure_conditions` 满足 | 密令锁定为失败，立即结算 `desire_on_failure` |
| **判定** | `evaluation_timing` 到达 | 计算最终完成度 |
| **结算** | 关卡结束 | 参与密令分配池分成，产出记忆碎片与渴望值 |
| **公示** | 结算后 | 按公开策略向全场揭示（见第 8 节未决问题 2） |

**"提前判负"必须立即告知持有者。** 一个守护对象已经死亡的玩家，应当马上知道自己失败了——因为这个瞬间正是渴望值的结算点，也是他后续行为（复仇、摆烂、伪装成仍在执行）的分岔口。让他蒙在鼓里没有任何设计收益。

### 2.4 呈现原则

- **密令常驻显示**，不藏在二级菜单里。玩家在每一次决策时都应当看见它。
- **完成度实时可见**，但只对持有者可见。
- **只显示判定所需的事实**，不显示达成建议。系统绝不提示"你应该去说服 5 号"。
- **不显示密令的稀有度或奖励权重的具体数值**，只给定性描述（"这条密令的代价高得离谱"）。让玩家凭感觉估价，是伪装与谈判的前提。

## 3. 密令分类

### 3.1 猎杀型

**内核**：让特定对象出局。制造关卡内最直接的敌意。

- 让 7 号在你之前出局。
- 使当前余命最高者在本关结束时余命低于 5 日。
- 让至少三名编号在第 4 回合前出局，不论由谁造成。
- 使某位编号的密令失败（**元密令**：你要破坏的是别人的目标，而不是他的命）。
- 让本关的生肖行使权柄超过三次（把矛头指向主持者）。

**注意**：猎杀型必须限量。若一局中猎杀型占比过高，关卡会退化为无差别混战，猜疑链反而消失——因为所有人都在杀人，杀人不再是线索。

### 3.2 守护型

**内核**：保住特定对象，即使代价是自己。**这是全系统中情感浓度最高的一类。**

- 保护 3 号存活至关卡结束，即使你自己出局也算完成。
- 确保没有任何编号在第 3 回合前出局。
- 让某位编号在结算时余命高于入场时。
- 保证 6 号的密令达成（你要帮一个不知道你存在的人完成他的秘密）。
- 使本关无人使用回响。

**关键接口**：守护型密令失败时产生**最高等级的渴望值**。"眼睁睁看着你的密令保护对象死去"是回响觉醒的核心触发源之一，直接对应创伤类型中的**无力**。守护型密令是渴望值经济的主要供给方。

### 3.3 约束型

**内核**：禁止你做某件事。它不要求你影响别人，只要求你**克制**——而克制在博弈中是最容易被看穿的。

- 全程不主动加注一次，并活到最后。
- 本关内不得说出任何编号的号码。
- 不得投票给任何人（弃权不算违反）。
- 不得成为任何一回合的最后一名行动者。
- 本关内不得获得任何余命（收益归零也算达成）。

**设计价值**：约束型密令让玩家的行为出现**无法解释的规律性**，而其他玩家会去解释它——通常解释错。它是猜疑链最廉价、最稳定的燃料。它同时与回响的**禁忌类**触发条件同构，是玩家理解禁忌类条件的入门教具。

### 3.4 操纵型

**内核**：让别人做某事。要求你影响他人行为而不暴露动机，是难度最高、也最有表演性的一类。

- 让 5 号在本关内至少弃牌三次。
- 使某位编号主动公开他自己的密令。
- 让全场至少半数编号在同一回合做出相同选择。
- 使某位编号对你产生公开的指认（你要让别人怀疑你）。
- 让某位编号把余命交给第三方。

**注意**：操纵型的判定必须锚定在**被操纵者的公开行动**上，绝不能锚定在"被操纵者相信了什么"。前者可裁决，后者不可。

### 3.5 信息型

**内核**：获知某事。它把玩家的注意力从"杀谁"转向"看谁"，是记忆碎片的主要产出渠道。

- 得知至少两名编号的密令分类（不需要具体内容）。
- 找出本关中持有守护型密令的那个人。
- 读取本关中所有刻印。
- 确认本关生肖的权柄归属（十二权柄中的哪一系）。
- 在结算前正确指出谁将成为本关名次第一。

**接口**：信息型密令是 `memory_reward` 的主要来源，因此**求真者画像的玩家会主动追求信息型密令**——见[余命与记忆经济](./02-economy-lifespan-memory.md)第 4 节。

### 3.6 自毁型 / 献祭型

**内核**：你的胜利就是你的失败。它是双池结算模型存在的理由。

- 在第 5 回合前主动出局。
- 使自己的余命在结算时低于入场时的一半。
- 成为本关第一个出局者，且出局时无人投票给你（你必须自己走向死亡）。
- 把你的全部余命输给指定编号。
- 让自己被全场一致指认为叛徒。

**设计价值**：自毁型密令的持有者会做出**在公开信息下完全非理性的行为**，而其他玩家会试图为这种非理性寻找解释。它是最强的误导源，也是"输家可能是最大赢家"的直接实现。**其 `reward_weight` 应显著高于其他类别**，否则没有人愿意执行。

### 3.7 复合密令（后置内容）

高日层可出现两段式密令：前半段是约束型，达成后解锁后半段猎杀型。例如：

- 「前四回合内不得投票 → 解锁：使第五回合的投票结果与你的意愿一致」
- 「找出持有自毁型密令的编号 → 解锁：阻止他达成」
- 「保护 3 号存活到第六回合 → 解锁：亲手让他出局」（**背叛型复合密令**，情感冲击最强的一类）

复合密令**建议放到主持期之后**。它会让分配变得棘手：前后两段的冲突标签不同，等于关卡中途要重新洗一遍所有人的对立关系，而可达性（6.3）必须对每一段分别成立。

## 4. 与其他系统的接口

### 4.1 与余命

- 密令完成度直接决定**密令分配池**的分成（见[余命与记忆经济](./02-economy-lifespan-memory.md) 5.1）。
- 分配采用相对份额：`密令分配池 × (个人完成度 / 全场完成度总和)`。这意味着**当全场密令普遍失败时，唯一达成者会拿到巨额回报**——高风险密令的期望值由此成立。
- 自毁型密令的高权重是经济上的补偿，让"主动去死"成为一种可计算的投资。

### 4.2 与回响

密令是**渴望值的主要生产装置**。

| 密令情形 | 渴望值 | 对应创伤类型 |
|---|---|---|
| 守护型失败（对象死亡） | 极高 | 无力 |
| 被结盟对象破坏而导致密令失败 | 高 | 背叛 |
| 密令被他人识破并公开处刑 | 高 | 湮没 / 欺瞒 |
| 约束型在最后一刻功亏一篑 | 中 | 剥夺 |
| 因执行自毁型而被全场唾弃 | 中 | 弃绝 |

**判定原则与意识涣散一致**：只有**真实付出努力后仍然失败**才产生渴望值。开局即放弃、全程无有效行动的密令失败不计入。**放弃的人不会有渴望。**

反向接口：**巳·蛇（谎言）系回响**可以伪造密令的公开呈现；**子·鼠（窃取）系回响**可以窥看他人密令的分类；**申·猴（诡辩）系回响**可以对密令的达成判定提出再解释。详见[回响系统](./04-echo.md)与[十二权柄与生肖](./05-zodiac-authority.md)。

### 4.3 与生肖收成

**密令冲突越激烈，收成越高。**

收成评分中的"背叛发生次数"，其准确定义就是**密令冲突的实际爆发次数**（结盟后因密令而背叛、守护型与猎杀型正面碰撞、操纵型成功诱导他人自毁）。

这产生了一个健康的激励闭环：生肖为了收成，会在关卡包中配置**互相咬合的密令池**，而不是一堆彼此无关的独立目标。**生肖的经济利益与玩家的戏剧体验方向一致。**

### 4.4 与关卡包

- 关卡包作者可以定义**自定义密令池**，并声明该池与基础玩法模板的绑定关系。
- 作者可为密令池设置**分类配比约束**（如"本关必有至少一条自毁型"）。
- 作者不能定义 `success_conditions` 中关卡不会产生的事件——这是 UGC 的可裁决边界，与"创作者只做规则组合"的原则一致。
- **压制**设置会影响密令：一个封锁窃取类回响的关卡，会让信息型密令显著变难，作者需要为此调整 `reward_weight`。工具应给出提示。

## 5. 可见性与泄露

### 5.1 默认状态

**完全私密。** 只有持有者可见，系统不向任何人（包括生肖）展示他人的密令内容。生肖只能看到**全场密令的分类分布统计**，用于主持时的临场判断。

### 5.2 主动公开

玩家可以随时说出自己的密令——**说出来这个行为本身系统不阻止，也不验证**。这里的设计核心是：

> **系统不提供任何"自证密令"的手段。**

你可以说"我的密令是保护 3 号"，但你无法证明。别人也无法证明你在撒谎。这一条是整个可见性设计的地基，第 7 节的反作弊完全建立在它之上。

对于 `disclosure_policy` 为「公开需付代价」的密令，玩家可以选择进行**系统认证的公开**：支付余命，由系统向全场广播"7 号的密令确实是猎杀型"（只公开分类，不公开对象）。这是唯一可信的公开渠道，因而极其昂贵，且**一旦认证公开就不可撤回**。

### 5.3 泄露惩罚

对于 `disclosure_policy` 为「不可告知」的密令，任何形式的主动透露都会触发 `leak_penalty`：

| 惩罚类型 | 效果 | 适用 |
|---|---|---|
| **作废** | 密令立即失败，无完成度 | 高奖励密令的配套代价 |
| **减成** | 完成度上限下调（如封顶 50%） | 常规惩罚，较温和 |
| **反转** | 密令目标反转（守护变猎杀） | 叙事效果最强，慎用 |
| **无** | 可自由讨论 | 低难度密令 |

**泄露的判定**是难点：没有任何可靠办法去理解玩家的自然语言聊天。可行方案是把"告知"限定为**结构化的游戏行为**（使用系统提供的"出示密令"交互、在系统投票界面公开指认），而**纯聊天中的口头透露不触发惩罚**——这在设定上也讲得通：终焉之地惩罚的是"出示"，不是"说话"。口头透露的风险由玩家自己承担（因为没人能验证，所以口头透露往往被当成谎言，这本身就是最好的自然惩罚）。

### 5.4 被识破

其他编号可以对你发起**指认**（结构化行为，消耗一次每回合有限的指认机会）：

- 指认内容只能是**分类**级别（"我认为 7 号持有守护型密令"），不能指认具体内容。
- 指认正确 → 目标密令的 `visibility_state` 变为「已被证实」，其完成度获得**减成**（因为被识破后更难执行），指认者获得余命奖励。
- 指认错误 → 目标 `visibility_state` 变为「已被误指」，**指认者被公开记录为误判**，且目标获得少量渴望值补偿。

误指的公开记录是关键：它让"乱指认"有社交成本，也给伪装留下了操作空间。

### 5.5 伪装密令

玩家可以主动**表演**一条自己没有的密令。系统对此的支持是**消极的**——不提供伪装道具，不提供假密令卡，只是单纯地不验证任何口头声明。

唯一的例外是**巳·蛇（谎言）系回响**：它能让玩家在系统层面**伪造一次"认证公开"**，即支付代价后由系统广播一条虚假的分类认证。这是全游戏中最强的社交武器之一，也解释了为什么巳·蛇系回响的触发条件必须极其苛刻。

## 6. 分配算法要求

分配算法的目标：**让一局的密令组合互相咬合，但不必然死锁。**

### 6.1 冲突度指标

把一局的密令建模为一张**冲突图**：节点是编号，边是密令产生的指向关系（`conflict_tags`）。

```
冲突度 C = 对立密令对数 / 参与人数
```

对立密令对的定义：两条密令的 `conflict_tags` 中存在同一对象上的互斥标签（`杀:3号` vs `保:3号`），或存在行为互斥（`禁:加注` vs `迫:3号加注`）。

**目标区间：C ∈ [0.35, 0.55]。**

- C 过低 → 全场各干各的，关卡沦为多人单机，没有社交推理。
- C 过高 → 全场立刻进入互相攻击，猜疑链来不及形成就被暴力解决。

### 6.2 配对约束

必须满足的硬约束：

1. **成环不成对。** 猎杀型与守护型的指向关系应尽量构成 3–4 人的环（A 杀 B、B 杀 C、C 杀 A），而非 1v1 对冲。1v1 会迅速演变为两人死斗，其余八人旁观。
2. **单点指向上限。** 任何一个编号被指向（被杀 / 被保 / 被操纵）的密令总数 ≤ 3。超过会让该编号成为全场焦点，体验极差且必然速死。
3. **被指向覆盖率。** 至少 60% 的编号应被至少一条他人密令指向，避免出现完全无人关心的"透明人"。
4. **喘息配额。** 至少 20% 的密令应为**无对象的自完成型**（约束型、信息型中的一部分）。这些玩家是关卡里的中立观察者与信息贩子，也是伪装表演的最佳载体。
5. **自毁型限额。** 每局自毁型密令 ≤ 2 条。过多会让结算变成一场自杀竞赛。
6. **猎杀型上限。** 每局猎杀型密令占比 ≤ 40%。

### 6.3 可达性校验（防死锁）

**"互斥"是特性，"不可达"是缺陷。** 必须严格区分：

- ✅ 允许：A 的密令与 B 的密令不可能同时达成（这正是我们想要的）。
- ❌ 禁止：某条密令在本关规则下**根本不存在任何达成路径**。

校验规则：

1. **规则可行性**：密令的 `success_conditions` 引用的每个事件，必须在本关基础玩法模板 + 规则修正件的组合下**有可能发生**。（例："全程不加注"在一个没有加注机制的投票关卡里是无意义的自动达成，应被拒绝。）
2. **压制兼容性**：若关卡对某类回响施加了**压制**，依赖该类回响的密令不得进入本局密令池。
3. **人数可行性**：`target_selector` 引用的位次或条件必须在当前人数下有解。
4. **时序可行性**：`evaluation_timing` 必须晚于 `success_conditions` 中最早可能达成的时点，且早于关卡的强制结束点。
5. **自动降级**：校验失败时不应报错中断开局，而是从备用池中替换为同类别、同难度档的密令。

### 6.4 难度配平

一局中的 `difficulty_tier` 分布应符合日层特征：

| 日层 | 低难度 | 中难度 | 高难度 |
|---|---|---|---|
| 试炼层（1–3 日） | 60% | 35% | 5% |
| 倾轧层（4–6 日） | 30% | 50% | 20% |
| 崩坏层（7–9 日） | 15% | 45% | 40% |
| 终焉（第 10 日） | 10% | 30% | 60% |

**新编号的第一条密令应当强制为低难度、无对象的约束型或信息型**，让玩家先理解"我有个秘密任务"这件事，而不是一上来就被要求杀人。

## 7. 反作弊

### 7.1 核心威胁：开黑交换密令信息

一队熟人在语音里互通密令，可以合谋瓜分密令分配池。这是密令系统最大的结构性风险。

### 7.2 地基：系统不提供自证手段

再次强调 5.2 的原则，因为它是所有缓解手段的基础：

> **除了昂贵且不可撤回的"认证公开"外，没有任何手段可以证明一条密令的真实内容。**

这意味着**开黑队友之间也无法验证彼此的说法**。合谋建立在"我相信你说的是真的"之上，而这恰恰是本作希望玩家体验的东西——**开黑者也必须承受猜疑链，只是他们的猜疑链更贵**。

### 7.3 缓解手段清单

| 手段 | 说明 |
|---|---|
| **不可告知密令** | 部分高价值密令的 `disclosure_policy` 设为「不可告知」，出示即触发 `leak_penalty`。开黑者要么放弃高价值密令，要么承担惩罚 |
| **延迟发放** | 部分密令的 `deal_time` 设为第 N 回合或事件触发，开局前的沟通无法覆盖 |
| **动态目标解析** | `target_resolve_time` 设为运行时解析（"筹码最多者"），开局时连持有者自己都不知道目标是谁 |
| **诱饵密令** | 向部分编号发放**表面相似但判定条件不同**的密令，使"我们密令一样"的判断不可靠 |
| **AI 编号稀释** | 检测到疑似开黑房间时，强制提高 AI 编号补位比例，降低队伍对全场的控制力 |
| **冲突图强制介入** | 分配算法优先把疑似同队编号配置为互相对立的 `conflict_tags`，让开黑队伍开局即内讧 |
| **认证公开的高定价** | 唯一可信渠道极其昂贵，使"互相认证以建立信任"在经济上不划算 |
| **战后异常检测** | 监控密令分配池收益的异常集中、同批编号高频同场、余命单向流动，先降低配对优先级而非直接封禁 |

### 7.4 明确不做的事

1. **不做聊天内容审查。** 系统不解析语音或文字来判断是否泄露密令，这不可靠且成本极高。泄露的判定只针对结构化行为（见 5.3）。
2. **不禁止组队。** 组队是社交游戏的正常需求，反作弊的目标是**让合谋不稳定**，而不是让合谋不可能。冲突图强制介入比封禁更符合世界观：终焉之地欢迎你带朋友进来，然后让你们互相残杀。
3. **不让任何玩家有机会看到别人的密令。** 除了持有者本人与结算时的公开环节，密令内容在任何时刻都不应出现在其他人面前——这是"每个人都有不能说的秘密"这条设计支柱的底线。

## 8. 未决问题

1. **口头泄露完全不受惩罚，是否会让"不可告知"形同虚设？**
   当前方案是只惩罚结构化的"出示"行为，口头透露完全自由。这是唯一不会引发争议的方案，但在体验上可能让 `leak_penalty` 字段大部分时候没有用武之地——玩家会直接口头说，反正没人能证实也没人会被罚。是否需要引入一个由 AI 主持人（生肖人格）进行的**主观泄露裁定**（AI 听到明显泄露则给予惩罚）？这符合世界观，但引入了裁量不一致与被诱导的风险。**需主创拍板。**

2. **密令是否应当在结算时全场公开？**
   全公开能制造极强的"真相揭晓"高潮，但也会摧毁跨局的伪装积累——一个惯用自毁型策略的玩家会很快被全服识破。备选：只公开已达成的密令，未达成的保持私密；或公开分类不公开内容。

3. **一人一条，还是允许多条？**
   当前设计是每人一条。多条密令会大幅提升策略深度与冲突度，但也会让玩家认知负担过重（尤其新编号），并使分配算法的可达性校验复杂度上升一个数量级。是否在崩坏层及以上开放"第二条密令"？

4. **AI 编号如何执行密令？**
   AI 编号必须真实持有并执行密令，否则老玩家能通过行为模式识别 AI 从而反推真人密令分布。但让一个靠外部模型驱动的 AI 编号可靠地完成一条结构化密令（尤其是操纵型与自毁型），难度很高。需要确定是采用"固定策略负责决策 + 外部模型只负责发言表演"的混合方案，还是完全交给模型自由发挥。

5. **冲突度目标区间 0.35–0.55 缺乏实证依据。**
   这个区间是凭设计直觉给出的起始值，必须在垂直切片阶段用真实对局数据校准。需要提前定义可观测的代理指标（对局时长、发言量、结盟形成率、背叛发生次数、玩家赛后评分），否则调参会变成盲调。
