## 0 · 两条不可妥协的约束

这两条决定了所有其他设计，必须在写第一行业务代码之前落地。

**约束 A · 规则事件流可独立复算。**

[13](13-record-and-inference.md) 的硬性验收是「删掉行为语料流后重放规则事件流，所有结算结果完全一致」。这要求规则内核是**纯函数式、无实时性、无隐藏随机、不依赖宿主对象生命周期**的。它不能是"界面顺手改了一下数据"的架构。

**约束 B · 事件载荷现在就要为未来系统备齐字段。**

渴望公式（[14](14-fragments-and-yearning.md)）需要「实际损失量 × 参与系数 × 抵抗系数 × 一致性系数」。四个因子的**原始事实**必须在 MVP 阶段就写进事件流，否则接入渴望引擎时要么改历史 schema，要么丢弃全部早期对局数据。按"以后要算什么"备字段，比以后补迁移便宜一个数量级。

## 1 · 分层

```text
┌─ 表现层    只订阅事件，不读状态，不含任何规则
├─ 会话层    权威端、命令上行、事件下行、可见性过滤、计时
├─ 模板层    某个关卡的阶段、命令、结算、潜规则与三张绑定表
├─ 内核层    纯数据、纯函数、可无界面运行、可重放
└─ 验证层    直设状态、跳转流程、快照导出
```

依赖方向**严格单向向下**，两条硬规则：

1. **内核层不引用任何具体模板的符号。** 这是"横向扩展关卡"能力的唯一实质保障，必须由目录级检查保证，而不是靠自觉。
2. **表现层不引用任何具体模板的符号。** 表现层按事件类型 + 模板提供的视图描述渲染。一旦界面直接依赖某个关卡的内部结构，第二个关卡就要重写整个界面层。

## 2 · 内核契约

### 2.1 三个概念的分工

| 概念 | 含义 | 可否被拒绝 | 是否改变状态 |
|---|---|---|---|
| 命令 Command | 玩家或 GM 的**意图** | 可以 | 否 |
| 事件 Event | 已经发生的**事实** | 不可以 | 是，且是唯一途径 |
| 归约 Reduce | `(状态, 事件) → 状态` | — | 纯函数：无随机、无 IO、无时间 |

### 2.2 唯一写路径

```text
命令 → 校验（读状态，产出拒绝理由或事件列表）
     → 追加日志（分配序号、时间戳、可见性）
     → 归约（改状态）
     → 广播给订阅者（表现层 / 日志 / 渴望引擎 / 推断管线）
```

**任何绕过这条路径修改状态的代码都是缺陷。** 状态字段一律只读暴露，写句柄只交给归约。

自动推进（无需命令即可前进的阶段）走同一条路径：推进函数返回事件列表，逐条提交；返回空列表表示当前需要等待命令。

### 2.3 事件结构

对齐 [13](13-record-and-inference.md) 的记录格式：

| 字段 | 含义 |
|---|---|
| 序号 | 整局单调递增、不复用；**两条流共用同一条轴** |
| 时间戳 | 权威端逻辑时间，仅供语料对齐，不参与判定 |
| 关卡轮次 / 协商轮 / 阶段 | 提交时的上下文快照 |
| 行动者 | 座位标识；系统事件为空 |
| 类型 | 事件类型标识 |
| 载荷 | 类型专属数据 |
| 流 | 规则流 / 行为语料流 |
| 可见性 | 公开 / 仅本人 / 指定名单 / 仅服务端 |
| GM 来源 | 是否由验证层注入 |

序号由单一计数器分配，两条流**共用同一条序号轴但分开存放**，于是"删掉行为语料流"在存储层面就是删一份数据，而不是过滤。

### 2.4 确定性规则

1. **规则数值一律用整数。** 余命、损失、承担值、奖励都是整数日。概率判定用百分比整数比较，不引入浮点。未来的渴望系数用定点整数表达。
2. **随机只有一个来源，且结果先写成事件。** 任何一次抽取（发密令、完美判定）必须把结果写进事件载荷；重放时不重新抽取，只读事件里的结果。
3. **禁止依赖容器的偶然顺序。** 一律按座位标识升序或对象标识升序迭代——插入顺序可能受网络到达顺序影响。
4. **内核不读系统时间。** 倒计时由会话层实现，超时以一个事件进入内核。

### 2.5 重放

重放只做一件事：**按序对规则事件执行归约**，不调用校验、不调用推进、不触碰随机源。

因此重放天然不受会话层、表现层、机器人策略影响。状态哈希基于状态的规范化文本形式计算，同时用于重放断言与 GM 快照。

### 2.6 内核模块职责

| 模块 | 职责 |
|---|---|
| 状态 | 纯数据容器：座位、余命、轮次、阶段，加一个模板专属状态对象 |
| 事件 / 日志 | 结构定义、序号分配、双流写出、按序号窗口查询 |
| 命令 / 校验结果 | 意图与拒绝理由 |
| 运行时 | 唯一写路径的编排者，持有状态、日志、随机源、事实投影 |
| 随机源 | 由种子完全决定；记录抽取次数便于比对 |
| 快照 | 状态与事件流的规范化与哈希 |
| 事实投影 | 对规则事件流的只读查询 |
| 事件订阅 | 供渴望引擎、推断管线、表现层挂载 |

## 3 · 模板接口

### 3.1 契约

```text
模板
  标识()                          → 模板标识
  人数范围()                       → 最小 / 最大
  阶段声明()                       → 阶段表（数据，非分支代码）
  初始状态(座位)                    → 确定性骨架；不得使用随机
  开局(状态, 随机源, 事实)           → 事件列表；随机结果写进载荷
  校验(状态, 命令)                  → 接受 / 拒绝 + 理由
  产出(状态, 命令, 随机源, 事实)      → 事件列表
  归约(状态, 事件)                  → 纯函数，无返回
  推进(状态, 随机源, 事实)           → 事件列表；空表示等待命令
  结算声明()                       → 经济核算的声明式描述

  谓词绑定()                       → 抽象谓词 → 本关事件投影
  锚点绑定()                       → 抽象锚点 → 本关效果
  创伤绑定()                       → 本关损失事件 → 创伤 W1–W8
```

**事实投影必须传给开局 / 产出 / 推进。** 密令求值与将来的回响激活判定都需要读事件历史，而它们都发生在模板内部。

⚠ 事实投影的构造必须是常数时间（引用日志，而不是拷贝）。批量模拟会反复调用投影查询，逐次拷贝会让整场模拟退化成二次复杂度。

### 3.2 三张绑定表

回响与模板两侧都说抽象语，中间夹一层模板绑定：

```text
回响侧（跨模板、跨轮回、永久）        模板侧（本关专属、可替换）
    抽象谓词    ←──── ① 谓词绑定 ────→   本关事件投影
    抽象锚点    ←──── ② 锚点绑定 ────→   本关效果动词
    创伤 W1–W8  ←──── ③ 创伤绑定 ────→   本关损失来源
```

**回响永远不知道自己跑在哪个关卡里**——这是它能跨模板存活的唯一原因。若激活条件直接写成"某枚灾痕"，这条回响就只能活在一个关卡里，与 [04](04-echo.md) 要求的跨模板映射直接矛盾。

三张表的性质完全不同：

| # | 表 | 方向 | 是否必需 | 缺失后果 |
|---|---|---|---|---|
| ① | 谓词绑定 | 回响**输入** | 可选，逐条 | 依赖该谓词的回响在本关不可激活 |
| ② | 锚点绑定 | 回响**输出** | **L1/L2 必须全实现** | 不得上架（[04](04-echo.md)） |
| ③ | 创伤绑定 | 渴望**输入** | 必需 | 本关不产生渴望，所有回响卡在渴望阈值上 |

②是强制的，这反过来要求抽象锚点集必须小而通用。③最容易被漏掉但同样致命。

### 3.3 上架校验：兼容矩阵

模板注册时做一次静态校验，输出全量矩阵：锚点覆盖率、谓词绑定率、以及**引用了无人绑定谓词的回响**。

两条判读规则：

- **未绑定谓词不是错误，是合法降级。** [04](04-echo.md) 已锁定行为：缺谓词 → 该关无法激活此回响，且**绝不让玩家为无效发动付费**——发动入口根本不出现。上架页如实公示即可。
- **无任何模板绑定的谓词 = 永远不会激活的回响。** 这种死条目不做校验就会静悄悄躺在库里，等着某天有人报"这条回响是不是坏了"。

### 3.4 玩具模板

除 T-11 外必须长期维护一个极小模板（两人、一轮、投票即结束）。

它唯一的作用是**证明内核没有偷偷依赖 T-11**。没有它，抽象接口会在半年内退化成"T-11 的另一个名字"。它属于测试资产，不属于内容。

## 4 · 谓词词表（回响激活的输入）

**词表是封闭的、平台维护的，不允许各模板自造。** 一旦放开，词表会碎成每个模板一套方言，回响的跨模板性当场归零。

扩词表是平台级决策，但代价是渐进的：谓词绑定可选，新增谓词不会破坏任何已有模板，只是引用它的新回响在没绑的关里不激活。

当前词表覆盖 MVP 四条回响所需：

| 抽象谓词 | 语义（跨模板） |
|---|---|
| 公开表态被背弃(x) | x 公开表态支持某方案，最终做了相反的选择 |
| 集体决议未通过(窗口) | 该窗口内的集体决议被否决 |
| 代价被他人承接(x, 我) | x 承接并实际结算了本应落在我身上的代价 |
| 转让请求被拒(从, 到, 窗口) | 一次转让请求被拒绝 |
| 收到的转让请求数(我, 窗口) | 他人向我发起的转让请求数 |
| 当前承担数(对象) | 对象当前承担的代价单位数 |
| 余命分位(对象) | 对象在存活者中的余命分位 |
| 当前强度档() | 当前难度/损失档位 |

三条实现纪律：

- **谓词只读规则事件流**，不读语料流、不读推断结果（[13](13-record-and-inference.md) 隔离第 1 条）。这也是「公开承诺」必须是结构化动作的原因：聊天里说"我认可"永远不能进判定。
- **必须可判定**，返回确定值或空；缺绑定时按 §3.3 降级。
- **投影可缓存但必须能从零重建**，缓存与重放结果不一致即测试失败。

**这笔成本 MVP 已经预付。** 密令的达成条件与回响的激活条件本质是同一种东西：对事件流的只读投影查询。要求只有一条——**别把这些投影写死在密令模块内部**，而要落在共享的事实投影层上。

## 5 · 语义锚点（回响效果的输出）

锚点是全体上架模板的强制义务，因此必须小而通用。已冻结为四条，真源见 [04](04-echo.md)：

| 抽象锚点 | 语义 |
|---|---|
| 揭示·一次已锁定的选择·L1 | 读取某编号已锁定但尚未公开的一次选择 |
| 重播·我的一次公开表态·L1 | 把我此前的一次公开表态重新置入当前公共区 |
| 转嫁·一次针对我的判定后果·L2 | 把他人承担的一份代价移到我身上 |
| 转嫁·我的一次判定后果到指定编号·L2 | 把我承担的一份代价移到指定编号身上 |

同一条回响在不同关卡里落成不同效果，回响本身一个字都不用改。L3/L4 按 [04](04-echo.md) 可先降级到同系 L2 处理。

**MVP 只做三件事，不做实现**：

1. 锚点注册表存在但为空，可用性判定恒为假。
2. 两个回响窗口阶段存在且零耗时穿过（见 §7.1）。
3. **所有持有者变更事件带来源字段**（自愿 / 回响强制），MVP 恒为自愿。

第 3 条不是可选的：潜规则明确规定回响强制移动**不点亮自愿参与灯**，这条差异是玩家推理链的关键。这三件事加起来很小，但它们决定了接入回响时是"加模块"还是"重构状态机"。

## 6 · 渴望引擎接入点

渴望引擎是**纯事件消费者**：订阅规则事件，不参与判定、不改变结算。接入时内核零改动。

### 现在就要备齐的载荷字段

[14](14-fragments-and-yearning.md) 的四因子对应的原始事实：

| 因子 | 需要的字段 | 承载事件 |
|---|---|---|
| 实际损失量 | 真实扣除值（**归零截断后的**，非名义值） | 损失结算 |
| 参与系数 | 本协商轮是否做过规则层行动 | 由顺序行动类事件投影 |
| 抵抗系数 | 是否申请过转移、是否投过反对 | 已有事件可投影 |
| 一致性系数 | 本次行动与自身密令方向是否一致 | 需在密令判定与行动事件间建立关联 |

前三项**自然齐备**，只要损失结算记的是截断后的实际值而非名义损失。第四项需要密令求值输出"哪些事件推进了该密令"的引用列表——这一项 MVP 就要做，因为它同时是 [13](13-record-and-inference.md) 的「证据强制引用」所需。

创伤映射（W1–W8）不在 MVP 实现，但 [14](14-fragments-and-yearning.md) 遗留的「密令类别 → 创伤映射表」是纯数据，密令定义里预留字段留空即可。

## 7 · T-11 的结构落点

规则真源是 [12](12-t11-last-proposal.md)，本节只写结构上的落点。

### 7.1 阶段表

九个阶段落成一张**数据表**，而不是一串分支：

| 阶段 | 接受的命令 | 推进条件 |
|---|---|---|
| 灾难显现 | 无 | 立即 |
| 顺序行动 | 承担 / 申请转移 / 回应 / 不选 | 所有存活座位各行动一次 |
| 分配检查 | 无 | 立即 |
| **回响窗口·分配** | （预留） | MVP 零耗时穿过 |
| 自由交流 | 公开承诺认可 / 就绪 | 全员就绪或超时 |
| 认可投票 | 锁定投票 | 全员锁定或超时 |
| **回响窗口·信息** | （预留） | MVP 零耗时穿过 |
| 投票揭晓 | 无 | 立即 |
| 结算 / 否决 | 无 | 立即 |
| 终局结算 | 无 | 见 §7.5 |

**两个回响窗口阶段现在就必须存在**，即使零耗时穿过。回响接入时只是给它们挂上处理器，不动状态机拓扑。这是最廉价的一次预留。

### 7.2 顺序行动与打断

被申请转移者的回应**不是新阶段**，而是顺序行动阶段内部的待回应子状态：

```text
顺序行动
  ├─ 当前座位提交「申请转移」
  ├─ 置待回应 = {申请者, 被申请者, 对象}
  ├─ 只接受被申请者的回应（其余命令一律拒绝）
  └─ 回应后清空，行动游标前进
```

回应**不消耗**被申请者本协商轮的行动；申请无论成败都消耗申请者的行动。

### 7.3 结算顺序与不变量

严格三步，且**同时扣除**：

1. 先全部算完，再一次性写入——禁止边算边扣
2. 立即检查归零并处理失守
3. 仅终局：最终承担奖 → 密令奖

**可推导的量不进状态。** 幕次与当前损失由轮次和本轮否决数推出，独立存储会在重放时两处不同步。

一条永久不变量，必须写进测试：`承担值总和 == 实际扣除总和`。

### 7.4 潜规则层

独立于主流程，只订阅事件：参与灯、环形脉冲、裂纹闭合、共同决策轮四条件、门环、完美判定。

完美判定的事件载荷必须同时记录**共同决策轮数、概率、抽取值、结果**。缺任何一项都会让重放漂移。

### 7.5 终局有三条路径，都要留档

| 路径 | 完美判定 |
|---|---|
| 打完全部轮次且全员存活 | 执行 |
| 打完全部轮次但有人失守 | 不执行 |
| 剩两人提前结束 | 不执行 |

第二条是**最常见**的一条。三条路径都必须无条件写出门环留档与**含共同决策轮数的终局事件**——否则批量模拟只能从"无人死亡"的对局采样，会系统性高估该指标的分布。

**终局必须拆成两步，中间隔一次提交。** 第一步宣告终局原因并发放最终承担奖，第二步才做密令求值——因为「余命处于存活者后 1/3」这类密令读的是**发奖后**的余命。同一批次内的事件对彼此不可见。

### 7.6 密令

密令表是数据（标识 / 难度 / 目标 / 配合标记 / 判定名），判定原语在绑定层。与谓词词表同构的取舍：**复用已有原语的新密令 = 纯数据**，只有真正的新条件才需要新增原语。

三条结构要求：

- 抽取结果先写成事件；密令只对本人可见。
- 局末一次性求值，只读规则事件流；每条成功判定**必须引用具体事件序号**。
- **记录与发放分开**：失守者不获奖，但判定结果仍然入档，只是发放额归零。历史档案才完整。

归因采用**参与式定义**（承诺 + 反对 + 该协商轮被否决），不区分是否关键票：严格的"移除这一票就会通过"在多张反对票时会导致全员免责。

发令器必须标记**依赖他人配合**的密令，并在批量模拟中**按密令标识分别统计完成率**——依赖他人的密令若系统性失败，会藏在平均值里。

## 8 · 可见性

权威端持有全部状态，客户端只收到被过滤后的事件。**可见性过滤必须在第一版就做**，事后补极痛。

| 内容 | 可见性 |
|---|---|
| 密令 | 仅本人 |
| 私聊 | 指定名单 |
| 锁定前的投票 | 仅本人；揭晓时才转公开 |
| 潜规则内部量（共同决策轮数、门环含义、完美概率） | **仅服务端，永不下发** |
| 世界内反馈（灯、裂纹、门环转动） | 公开，但**不附带任何解释文字** |

最后两条是设计要求：客户端**不能拿到**共同决策轮的计数值，否则可以直接读出潜规则。门环只下发"转了一格"这个事件本身——信息等价，但呈现方式强迫玩家自己去数、自己去关联。

## 9 · GM 与验证

[10](10-gm-and-validation.md) 要求 GM 能直设状态、跳转流程且不污染正式数据。

- **GM 操作也走命令 → 事件**，只是带 GM 来源标记。这样 GM 局同样可重放，也自动满足"导出状态快照、事件日志、随机种子和版本号"。
- 任何一局只要含 GM 来源事件，整局标记为 GM 局，结算结果不写入正式余命账本。
- 状态哈希同时服务于重放断言与 GM 快照。

## 10 · 测试策略

这套架构的全部价值都要靠测试兑现，否则会在三个月内退化。

| 测试 | 内容 | 对应验收 |
|---|---|---|
| 黄金重放 | 录一局 → 重放 → 状态哈希一致；同种子两次运行一致 | 约束 A |
| 单流重放 | 删除语料流后重放，结算数值完全一致 | [13](13-record-and-inference.md) |
| 不变量 fuzz | 随机合法命令序列，断言承担上限、余命非负、承担值总和等于实际扣除、失守者无后续行动 | 规则正确性 |
| 玩具模板 | 极小模板跑通全链路 | §3.4 横向扩展能力 |
| 兼容矩阵 | 锚点覆盖、谓词绑定、死条目 | §3.3 |
| 批量模拟 | 机器人跑大量对局，输出净回收 / 否决率 / 密令完成率 / 共同决策轮分布 | [12](12-t11-last-proposal.md) 经济验收 |

**参数扫描是测试设计的一部分。** 常规参数下不会出现的分支等于没测过——终局的"提前结束"路径就必须靠调低入场余命才能触发。设计用例时要主动覆盖参数空间，而不是只跑默认配置。

**批量模拟是这个项目性价比最高的一项投入**：[12](12-t11-last-proposal.md) 的全部数值都只是纸面推算，靠真人试跑验证需要几十局。有了确定性内核和机器人，这些数字一晚上就能跑出来，且能直接回答"否决会不会被用来刷奖池""哪条密令是白送的"这类结构性问题。

## 11 · 里程碑

| # | 内容 | 完成判据 |
|---|---|---|
| M0 | 内核：命令 / 事件 / 归约 / 日志 / 随机源 / 快照 | 黄金重放通过 |
| M1 | T-11 主流程（无潜规则、无密令、无界面） | 无界面跑完全部轮次，经济数字可复算 |
| M2 | 密令 + 事实投影 + 玩具模板 | 密令可求值；玩具模板不改内核即可跑通 |
| M3 | 潜规则层 + 表现层 | 玩家可从世界内反馈推出可推理链 |
| M4 | 会话层 + 可见性过滤 + 私聊 | 真人局可完整进行；抓包读不到潜规则量 |
| M5 | GM + 批量模拟 | [10](10-gm-and-validation.md) 三个必测场景可执行 |

M0–M2 是纯逻辑，无美术依赖，可以先行。回响、碎片、渴望、推断在此之后作为**新增模块**接入，届时只应触碰模板层与新增的回响模块，不动内核编排。
