# 14 · 前史碎片与渴望值

> 状态：核心规格 v0.1 ｜ 真源：碎片归属、找回度、渴望值与激活判定
>
> 回响生命周期见 [04](04-echo.md)；记忆的经济定位见 [02](02-economy-lifespan-memory.md)。

## 一句话定义

> **碎片是有归属的具名记忆；获得即自动拼回所属位置，只在发动回响时被烧掉。**

## 激活判定

一条回响 `E` 可激活，当且仅当同时成立：

```text
找回度(E) ≥ 找回阈值             慢门 · 跨轮回累积 · 真相轴
渴望值(E.创伤) ≥ 渴望阈值(E.阶)   快门 · 局内事件 · 生存轴
E 的共鸣与其余条款成立            瞬时门 · 模板情境谓词
```

三门由 [01](01-core-loop.md) 的三条长期轴分别供给，时间常数不同。语义：我找回了自己，眼前正在重演，而且我现在真的疼。

## 碎片

碎片是可辨识的叙事片段（如 E-03 前史的 `「他替我签了那份字」`），不是无差别计数。每枚天生属于一个确定位置：某条回响的前史，或真相轴。**玩家不分配**，获得即自动拼回，找回度随之上升，与 [01](01-core-loop.md) 的 `行为被观测 → 前史碎片 → 执念/回响形状` 一致。

| 获取来源 | 产出 | 归属 |
|---|---|---|
| 密令完成 | 低 / 中 / 高 = 1 / 1 / 2 枚 | 该密令类别对应的创伤 |
| 完成关卡 | 1 枚 | 真相轴 |
| 本局渴望增量最高的创伤 | 1 枚 | 该创伤的前史 |

第三条使两道门由同一伤口供给：**本局最疼的伤口，就是今晚想起一点的那段过去。** 该前史已满则顺延至次高。

掉落只读规则事件流，由渴望增量决定。[13](13-record-and-inference.md) 隔离第 1 条已禁止小模型参与，本节无例外。

## 找回度

```text
找回度(E) = E 的前史已持有碎片数 / E 的前史碎片总数
```

按回响独立计算，不是全局百分比。已拼回的碎片跨轮回永久保留，落在 [04](04-echo.md) 第 3 条的「形状」一侧。两个连带结论：

- [09](09-open-questions.md) C4「一轮回最多激活几条形状」改由碎片稀缺性约束，不设硬性上限。
- [02](02-economy-lifespan-memory.md)「记忆是否继承」定案一半：已拼回继承，且不存在未拼回的库存。

## 燃料与自噬

**没有游离库存**，发动只能烧已拼回的碎片。燃料量按 [04](04-echo.md) 阶数：L1 1 枚、L2 3 枚。

| 可烧来源 | 代价 |
|---|---|
| 本条回响自己的前史 | 找回度下降，可能当场失活 |
| 其他回响的前史 | 本条保住，被拆的那条可能失活 |
| 真相轴 | 回响全部保住，真相进度倒退 |

这是 [00](00-overview.md)「三者共用同一资源」的落点：共用发生在支付点，不在获取点。

自噬结算顺序固定：

1. 效果按模板完整结算
2. 扣除碎片，更新找回度
3. 找回度低于阈值则该回响**立即失活**，直到找回度重新达标

效果先结算，玩家不会付了代价拿不到效果；失活可在本轮回内通过重新掉落碎片解除。玩家总能看到自己正要烧掉哪几枚，但阈值只在掌握阶段可见，因此只有已掌握该回响的玩家能自行推算后果；不额外增设提示。不发动仍无任何成本。

## 渴望值

按创伤分池：`渴望值(W1) … 渴望值(W8)` 各自独立累积。语义是**反复被撕开的那个伤口才给你力量**；与 [13](13-record-and-inference.md) 的形状漂移共用同一套 W×R 坐标。

```text
渴望增量(W) = 实际损失量 × 参与系数 × 抵抗系数 × 一致性系数
```

| 因子 | 判定 | 拦截 |
|---|---|---|
| 实际损失量 | 实际扣除的余命日数 | 没真赔过就没有渴望 |
| 参与系数 | 做过规则层行动 1.0；全程不选 0 | 挂机吃伤害 |
| 抵抗系数 | 曾尝试规避 1.0；毫不抵抗 0.5 | 张开手挨打 |
| 一致性系数 | 与**自身密令方向**一致 1.0；明显自毁 0 | 故意送死 |

一致性对齐玩家自己的密令，不是普世正确打法；故 M-07【说话不算】与 [03](03-mandate.md) 自毁类密令都算一致，全额计入。

激活本就只持续当前轮回，故渴望在轮回边界大部分蒸发，只留残量使后续轮回更易重新唤醒同一伤口。对应 [09](09-open-questions.md) C2：部分累积 + 衰减 + 上限。

## T-11 的创伤供给

下表是**模板创伤供给绑定表**的第一个实例：每个上架模板都必须声明本关的损失事件分别喂养哪个创伤，否则该关不产生渴望，所有回响都会卡在渴望阈值上。工程形态见 [15](15-t11-technical-design.md)。

| T-11 事件 | 喂养 |
|---|---|
| 承诺认可后投反对、公开承诺后食言 | W1 背叛、W4 欺瞒 |
| 提出方案无人回应、承担最多却未获奖 | W8 湮没 |
| 转移申请被拒、无人愿意与我交换 | W5 弃绝 |
| 被迫承担、被 E-04 强制转来灾痕 | W3 剥夺 |
| 灾痕结算逼近归零 | W2 无力、W7 囚禁 |
| 他人因我的行动实际损失余命 | W6 罪咎 |

⚠️ **W6 不得绑定致人死亡**，口径须为「他人因我而实际损失余命」。E-03 需要 W6，6 人局未必常出现失守，绑死则该回响近乎不可激活；E-03 的共鸣条件「x 替我结算过一枚灾痕」本身即满足该口径。

## 可见性

两道门都挂在 [04](04-echo.md) 的理解进度上，以免撞上 [09](09-open-questions.md) 风险台账中「玩家不知道为何现在可用」。

| 理解进度 | 找回度 | 渴望值 |
|---|---|---|
| 觉醒前 | 碎片可见，不知属于哪条回响 | 不可见 |
| 辨认后 | 显示该伤口进度条 | 模糊刻度 |
| 掌握后 | 显示精确阈值 | 精确数值与阈值 |

## MVP 起始参数

全部待实测；目标是让四条回响在测试局里都够得到，不是平衡。

| 参数 | 起始值 |
|---|---|
| 每条回响前史碎片数 | 5 |
| 找回阈值 | 3 / 5 |
| 渴望阈值 | L1 = 2，L2 = 5 |
| 单个创伤渴望上限 | 12 |
| 渴望轮回保留比例 | 25% |

一个十日轮回约产 17 枚伤口碎片、10 枚真相轴碎片；四条回响填满需 20 枚，故拿不满，四条之间天然竞争。

## 验证

1. 找回度设到阈值上下各一枚，确认激活入口随之出现与消失。
2. 制造高渴望事件，确认按四因子计算，全程不选者增量为 0。
3. 确认掉落归属等于本局渴望增量最高的创伤；填满后确认顺延次高。
4. 发动 L2 并全烧本条自身前史，确认效果先结算、随后失活。
5. 进入新轮回，确认碎片全保留、渴望按比例衰减、激活状态清空。
6. 关闭推断管线，确认碎片掉落与渴望累积不受影响。
